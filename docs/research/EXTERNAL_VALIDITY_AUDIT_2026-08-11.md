# External validity audit — 2026-08-11

An 11-agent audit (4 code auditors, 2 research agents, 3 visual comparators over
a 23-capture matrix, 1 reference-image gatherer, 1 completeness critic) run the
evening after the ROOT DEFECT was identified. Trigger: perceived external
validity had fallen, with the hypothesis that the model is missing
**conditions-dependent swell direction**.

## Provenance and limits — read first

- Every visual claim below comes from **one frozen frame** (`sim=42`, 1280×720,
  default build: raw M4 locus, `#psi/#smooth/#peeldir/#nose` all OFF). The
  visual agents graded exactly the configuration MODEL.md §4.5.1 already
  declares invalid, and **no motion was observed** — zipper travel, set
  cadence, foam advection, and rider speed are unaudited.
- The quantitative twin-divergence numbers (rider bury depth, audio lag, line
  offsets) come from **hand-built Node replicas of the GLSL**
  (`twin_probe{,2,3}.mjs`, session scratchpad), never validated against actual
  GPU output. Treat as order-of-magnitude until a capture-based check exists.
- Two surfaces were **not audited**: the raymarch `web/` build, and the
  deployed `/pleasurepoint/` essay — whose published figures were generated by
  the same indicted default configuration.
- Capture harness: `scripts/capture_audit_matrix.mjs` (deterministic; presets ×
  drone/cliff/lineup, H₀ swing pair, tide pair, big day, rider).

## Verdict on the direction hypothesis: partially supported — and second-order

Direction is genuinely absent from the runtime, but it is **not** why external
validity fell. The break line is owned by DEM noise (the ROOT DEFECT), which
dominates the error budget by 1–2 orders of magnitude; a wired direction would
change nothing on screen until the reef owns the break line and a refraction
path actually consumes the angle.

### What the ocean actually does (CDIP, computed this session)

From 16 months of THREDDS data — deep water: CDIP buoy 156 archive
(`156p1_historic.nc`, 22,323 records); at the break: MOP `SC116_nowcast.nc`
(11,953 hourly records, 15 m contour ~150 m off PP):

- **Deep water Dp spans ~100°** (210–307° p1–p99), NW 280–300° holds 63% of
  records; period-structured — Tp 8–12 s arrives ~291°, 16–25 s ~245° with a
  tail to 230° (long S/SW groundswell).
- **At 15 m it collapses to ~30°**: Dp 187–221° (p1–p99), 90% of hours within
  188–216°, median 194°. Matched-hour regression of nearshore on deep Dp:
  slope 0.067 (r = 0.18, n = 11,161). Monterey Bay refraction + shadowing do
  almost all the funneling — the sim's fixed per-spot α is much closer to
  truth than raw deep-water variability suggests.
- **But the residual is systematic, not noise**: monthly medians swing ~18°
  (Dec–Feb 203–209° = wrapped NW; Jun–Aug ~191° = direct S); Tp 8–12 s
  windswell arrives ~215° vs 16–25 s groundswell ~192°. Against a ~200° shore
  normal (UNVERIFIED — check before quoting an asymmetry story), incidence at
  15 m spans roughly −12°…+21° off normal.
- Dp is a single-partition peak: real combo days superpose S + NW trains,
  which a single incident direction cannot represent (see conditions gap
  below).

So the honest refinement: the missing signal is a **~15–30°,
seasonally- and period-structured incident-direction band**, first-order for
peel geometry — worth wiring, after the break line is real.

### Direction in the code (all confirmed at file:line)

- `#swell=` is a **dead knob**: written at `web-three/js/main.js:800`, read
  nowhere in either build; the refraction bake receives `swellDeg: state.alpha`
  (`main.js:629`).
- `#day=live` **fetches Dp and drops it by design**: `web/js/cdip.js:44/49`
  parse `waveDp`, `describeOcean` prints "from N°" in the HUD, `applyOcean`
  (`cdip.js:68–72`) copies only Hs and Tp. The HUD announces a direction the
  model ignores.
- `bakeBreakLine`'s cache key (`bed.js:702`) **omits direction** while the
  peel-direction constraint consumes it inside the bake — a latent stale-bake
  bug the moment direction varies at runtime (masked today because α only
  changes with `spotName`).
- **α is semantically overloaded**: deep-water swell direction (`main.js:393`,
  `:629`) *and* per-spot peel character (`params.js:61–67` authors 38–70°
  across presets that would face the same physical swell). Making direction a
  condition requires a MODEL.md-level variable split (site character vs ocean
  state) plus a per-spot compass→contour-frame constant that does not exist
  anywhere in the repo (the shoreline tangent swings ~110° along the point, so
  it cannot be global).
- Otherwise the math core is **already direction-parameterized end-to-end**
  (`alongshoreKappa`, `bakeRefraction`/`incidenceAt`, `swellPhi`/`u_alpha`
  re-copied per frame): conditions-driven direction is a rebake-triggering
  problem, not a math problem.

## What the captures show

Scene-level external validity at drone altitude is near zero, and the failure
modes are the ROOT DEFECT made visible plus two independent scene gaps:

1. **No headland.** Every drone frame reads as a near-straight generic beach;
   the defining ~110° Pleasure Point corner cannot appear because the
   coastline is a per-spot re-centered low-order curve. Land is a featureless
   tan blob. (Compare `sat_usgs_z16` NAIP ortho: kelp wedge tracking the reef,
   swell lines wrapping the corner.)
2. **Beach-break break geometry.** All seven spots render 2–3 simultaneous
   shore-parallel whitewash rows; no frame contains a single-takeoff zippering
   point. Pairwise RMSE between the six land-bearing drone frames is
   0.049–0.093 — the spots share one water template and differ only by
   coastline silhouette.
3. **Authored α is visually erased.** Snell refraction collapses 38–70° of
   authored direction to ~8–10° of visible crest angle at every spot — so even
   the *authored* direction story never reaches the pixels.
4. **The one "peel" marker is an artifact**: a dashed cross-shore whitecap
   streak perpendicular to the crests, locked to a hard vertical seam in the
   water shading (seam cause unidentified — NOT the Ψ bake, which was off in
   every capture).
5. **Conditions responses are wrong in kind:**
   - H₀ 1.5→1.8 m (same clock): foam coverage +55% (graded, healthy channel)
     but the only discrete crest marker *vanishes* rather than shifting
     seaward (discontinuous, the broken channel).
   - Tide −0.8 vs +0.7 m: waterline translates correctly, but breaking
     *intensity inverts* (low tide glassy, high tide more active — backwards
     for a reef) and the surf zone does not reposition. Root-cause before
     wiring live tide; a live screensaver that is reliably wrong in the
     most-checked variable is worse than a frozen one.
   - H₀ 2.8 m: reads as distant translucent glass lumps over a calm lagoon —
     disconnected crest islands (root defect), *less* foam than the default
     day.
6. **Water-level look targets** (vs VISUAL_GROUND_TRUTH.md): marine-layer
   atmosphere PASS (diffuse, no glitter at water level, fogged horizon).
   Everything carrying the surf read fails: foam-first read FAIL (~20-value
   foam/water step vs ~130 in photos, foam detached from crests); three-tone
   value structure FAIL (faces render *lighter* than flats — inverted; note
   the under-steepened LAM=90 geometry predicts part of this, so don't tune
   fresnel against broken geometry); foam aging FAIL (code exists,
   `shaders.js:469/603`, renders as uniform blur); kelp/crowd/riprap absent;
   Lineup camera — the canonical surf-photography view — shows an **empty
   ocean** in all three lineup captures.
7. **Rider confirmed on the wrong surface visually**: stick figure standing
   upright on flat open water tens of meters from the nearest crest
   (`rider_secondpeak_cliff.png`).

## Twin divergence (replica-derived numbers — see limits)

Two orthogonal axes:

- **Break line**: the JS twin never grew the `u_breakMix` branch
  (`model-js.js:116–121` vs `model-glsl.js:222–235`), so with M4 on by default
  every CPU consumer is keyed 15–108 m sideways of the drawn line — rider
  (board ~1.9 m under the drawn surface at Sewers, floated at Second Peak),
  sound (crash mask 0.00 during the visible crash; ~7–20 s late), camera aim
  (5–9° error on a 30° FOV).
- **Depth path**: twin `oceanH` has no `growGeo`/`Hlim`/gate/`shoreFade`/skew/
  lift — 0.77 m rms, 3.3 m max vs the GPU replica even on the authored line.
- **The acceptance instrument is circular**: `rideMetric` (`main.js:887–901`,
  consumed by `scripts/measure_ride.mjs`) scores through the displaced twin,
  so the published 0.81–0.87 face-height ratios certify twin self-consistency,
  not rider-on-drawn-wave. No test compares the two implementations, so this
  drift class recurs silently.

## Conditions representability (code audit)

Live: **2 of ~10** real ocean-state dimensions (Hs, Tp — both silently clamped,
3.0 m / 18 s). Authored per day-bundle: tide, chop, dF, tau (a "live" day
inherits all four from whatever preset was active). Absent entirely: direction
(above), directional spread, second swell train (structurally unreachable —
one monochromatic carrier; dF is set rhythm, not bandwidth), wind as data
(one 0–1 chop scalar, compile-time drift direction `shaders.js:52`), sky state
(sunDir hardcoded `shaders.js:78`; glitter can never follow sun visibility).

## Priority ordering (audit's recommendation)

1. **Root defect first** — nothing else pays off while the reef doesn't own
   the break line. Next cheap probe stands: sample `lift` along 38th's crest
   line; if the deepened nose dives below the natural bed, deepen relative to
   the bed, not a fixed datum.
2. **Twin honesty** — port `u_breakMix` + the depth path into the twin (or
   re-key rideMetric to the GPU surface). Until then treat all acceptance
   numbers as self-referential. Add a CPU-vs-GPU parity test to kill the
   silent-drift class.
3. **Direction plumbing, gated on a MODEL.md §4.5 variable split** — split α
   into site character vs incident direction, add per-spot compass→contour
   constants, fix the `bakeBreakLine` cache key, then wire `o.dp` through
   `applyOcean`. Cheap mechanically; doctrinally it must not be asked to carry
   spot identity (that's the reef's job).
4. **Tide polarity root-cause** before any live-tide wiring.
5. **Renderer reads, after geometry**: foam attachment/brightness/aging (the
   single largest water-level gap), face darkening (tune only after `#psi`
   lands, to avoid baking a compensation), then kelp/crowd/cliff cues.
